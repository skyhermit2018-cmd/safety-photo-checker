# 산업안전 사진 판독 (Safety Photo Checker)

현장 사진 한 장을 올리면 AI가 **위험 요인**과 **산업안전보건 법령 위반 소지**를 조문과 함께 정리해 주는 정적 웹앱입니다.
건설·산업현장 안전관리자가 스마트폰으로 촬영해 바로 확인하고, 결과를 카톡·보고서에 붙여넣는 흐름을 목표로 만들었습니다.

- 배포 주소: <https://skyhermit2018-cmd.github.io/safety-photo-checker/>
- 빌드 없음. HTML/CSS/JS 정적 파일만으로 동작하며 서버·중계 백엔드가 없습니다.
- API 키는 사용자의 브라우저 `localStorage`에만 저장되고, 사진은 선택한 AI 제공사(Google/OpenAI)로 브라우저에서 직접 전송됩니다.

## 주요 기능

| 구분 | 내용 |
| --- | --- |
| 사진 입력 | 파일 선택, 모바일 카메라 촬영(`capture="environment"`), 드래그 앤 드롭, 클립보드 붙여넣기 |
| 전송 최적화 | 업로드 시 canvas로 최대 1280px·JPEG 품질 0.82로 축소(원본은 저장하지 않음) |
| 공종 선택 | 자동 판별 + 고소작업·비계 / 전기·가설전선 / 굴착·흙막이 / 양중·크레인 / 개인보호구 / 화기·용접 / 밀폐공간 / 정리정돈·통로 |
| AI 제공사 | Google Gemini(`gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-2.0-flash`), OpenAI(`gpt-4o-mini`, `gpt-4o`) |
| 키 관리 | 입력·보기·테스트·저장·삭제, 제공사별 모델 선택 |
| 결과 | 종합 위험등급(위험/주의/양호), 위험 요인별 위치·내용·신뢰도, 관련 법령과 위반 소지, 즉시 조치 체크리스트, 법령 근거, 확인 필요 사항 |
| 내보내기 | 보고용 텍스트 복사(카톡·문서용), 인쇄 및 PDF 저장(`window.print()`) |
| 기록 | 최근 점검 20건을 `localStorage`에 저장(썸네일 포함, 용량 초과 시 썸네일부터 정리) |
| 법령 참고 | 앱이 AI에게 함께 전달하는 조문 목록을 화면에서도 확인 가능 |

## API 키 발급

1. **Google Gemini (무료 티어)** — <https://aistudio.google.com/app/apikey> → Google 계정 로그인 → API 키 만들기
2. **OpenAI** — <https://platform.openai.com/api-keys> → Create new secret key (선불 크레딧 필요)

앱 우측 상단 **API 키** → 제공사 선택 → 키 붙여넣기 → **키 테스트** → **저장**.

## 파일 구조

```
index.html            화면 구조
assets/style.css      모바일 우선 스타일, 인쇄용 스타일 포함
assets/app.js         사진 처리·AI 호출·결과 렌더·기록 관리
assets/legal-data.js  AI에게 전달하는 참고 조문 데이터
.nojekyll             GitHub Pages에서 파일을 그대로 서빙
```

## 법령 인용 기준

`assets/legal-data.js`의 조문은 국가법령정보센터 원문으로 확인했고, 「산업안전보건기준에 관한 규칙」은 **[시행 2026. 3. 2.] [고용노동부령 제450호]** 기준입니다.
법령은 개정되며 조문 번호가 이동할 수 있습니다(예: 굴착면 기울기 조문은 2023. 11. 14. 제338조 → 제339조로 이동). 앱은 AI에게 **이 목록에 있는 조문만 번호를 인용**하도록 지시하고, 목록에 없는 내용은 조문명만 쓰도록 제한합니다.

## 한계와 주의

- AI 판독 결과는 **현장 점검 참고용**입니다. 최종 법적 판단은 안전관리자와 법령 원문 확인이 필요합니다.
- 사진에 담기지 않은 조건(높이, 하중, 작업계획서, 교육 이력, 지반 상태 등)은 판단에 반영되지 않습니다.
- 사진에는 근로자 얼굴 등 개인정보가 담길 수 있습니다. 필요한 부분은 가리고 촬영하세요.
- 공용 기기에서는 사용 후 **저장된 키 삭제**를 권장합니다.

## 로컬에서 실행

```bash
python3 -m http.server 8000
# http://localhost:8000
```

`file://`로 열어도 화면은 뜨지만, 브라우저에 따라 API 호출이 차단될 수 있으므로 로컬 서버 사용을 권장합니다.

## 배포

GitHub Pages에서 **`gh-pages` 브랜치 루트**를 소스로 서빙합니다(Free 계정·public 저장소). `main`이 작업 브랜치이므로, 내용을 고칠 때는 두 브랜치를 함께 갱신하세요.

```bash
git push origin main && git push origin main:gh-pages
```

`.nojekyll`이 포함되어 Jekyll 처리 없이 정적 파일이 그대로 올라갑니다.

> Pages 소스를 `main`으로 바꾸고 싶다면 저장소 → Settings → Pages → Branch를 `main / (root)`로 한 번 저장하면 됩니다. 이후에는 `main`만 푸시해도 반영됩니다.

## 검증 기록 (2026-11-20)

- 배포 URL 200 OK, `index.html`·`assets/*` 모두 200 (콘텐츠 타입 정상)
- 실제 브라우저에서: 9개 공종 칩·48개 참고 조문 렌더, 키 설정 모달 열기/제공사 전환/모델 선택, 키 저장·삭제, `localStorage` 반영 확인
- Gemini 키 테스트: Google API에 실제 도달해 "API 키가 올바르지 않습니다"로 정상 매핑(잘못된 테스트 키 사용)
- 사진 업로드: 1920px PNG → 1280×662·45KB JPEG로 축소·미리보기 표시
- 판독 파이프라인: 요청 전송·오류 패널·취소·진행 상태 표시 동작
- 결과 화면: 위험등급·위험요인·법령·조치·법령근거·확인필요 렌더, 보고용 텍스트 복사, 인쇄로 2페이지 PDF 생성(입력 카드 제외하고 결과만 출력)
- 기록: 2건 저장·목록·다시 열기·개별 삭제·전체 삭제(확인 대화상자) 동작

OpenAI 경로는 이 검증 환경(데이터센터 원격 브라우저)에서 `api.openai.com` 요청이 전송 단계에서 차단되어 실제 호출을 확인하지 못했습니다. 일반 휴대폰 네트워크에서의 확인이 필요합니다.

## 개발·검증용 훅

`?debug=1`로 열면 `window.__SPC_DEBUG`(`normalizeResult`, `renderResult`, `buildReport`, `addHistory`, `renderHistory`, `loadHistory`)가 노출됩니다. API 키가 실제로 없어도 결과 화면을 확인할 때 씁니다. 일반 사용에는 영향이 없습니다.
